# 香港升学＋身份联合筛选问卷

当前交付是**可运行、未公开发布的待确认版本**。原聊天正文未能返回，因此题库是按需求重建的15题核心＋6题条件题，不得称为原21题逐字沿用。题库、运营主体与隐私文案需要最终确认。

## 预览

需要 Node.js 22 或更新版本。在项目目录执行 `npm start`，打开 http://localhost:4173 。后台地址 http://localhost:4173/admin.html 。默认预览模式完成填写不保存资料，后台接口关闭。`npm test` 使用虚构资料验证分支、评分、权限、加密存储及删除。

## 已实现

五步手机问卷；返回修改；按香港身份、赴港计划和目标显示分支；必填验证；必要隐私与联合团队共享授权、单独可选营销授权；服务器重新验证及计算E/I；加密持久化存储；后台密码登录、分流筛选、查看完整答案、删除、退出。一小时后台会话仅存在内存中，服务重启使会话失效。不会把家长资料写入代码仓库，也不在浏览器持久保存答案或登录令牌。

15核心题：目标、学习阶段、当前课程、成绩、英语、希望路线、启动时间、赴港安排、身份现状、身份考虑、年度教育预算、身份服务预算、家庭决策、城市、称呼及电话。6条件题：学历、工作年限、赴港工作安排、续签需求、预算组成、主要顾虑。

E：升学目标25＋启动时间25＋成绩20＋英语15＋决策15。
I：身份目标25＋身份意向25＋启动时间20＋身份状态15＋决策15；明确不考虑身份或无需身份服务时为0。E/I均≥60分流联合顾问，仅E≥60分流升学，仅I≥60分流身份，否则初步咨询。学历和工作年限只供人工核实，不自动判定申请资格。预算分别显示原始申报，缺费用组成则提醒拆分；本版没有未经依据的路线费用报价。

## GitHub Pages前端＋独立后端

1. 用户连接并授权GitHub，确定仓库。仓库只包含源代码，本项目`.gitignore`和`.dockerignore`排除数据及秘密；运营数据目录必须挂载到仓库之外。
2. 选择经运营方批准的数据存储地域和后端服务。该后端可用Docker部署到支持**持久磁盘**和HTTPS的服务或自有服务器。不能放在无持久磁盘的函数环境或GitHub Pages。单实例运行，不支持多副本共享目录。备份必须加密，密钥独立存储。
3. 在托管平台安全设置中填写`.env.example`所列变量。`DATA_KEY`是64位十六进制随机密钥（32字节）；`ADMIN_PASSWORD`至少16字符并随机生成。不要在聊天、公开仓库、前端配置中放密码或密钥。当前是单管理员账号；若需多人员访问，发布前应接入各自账户和审计，不共享密码。
4. 配置准确的HTTPS `PUBLIC_ORIGIN`（例如GitHub域名，**不含仓库路径**）与`ADMIN_ORIGIN`。代理转发至4173，公网仅暴露HTTPS，不直接开放后端端口。后端速率限制按真实连接地址计数；反向代理部署须在网关另外配置按真实访客IP的速率限制。本程序不信任任意转发头。
5. 运营方批准主体、接收团队、存储地域、保存期限、隐私联系邮箱及最终隐私告知。编辑`public/index.html`的隐私草案与合作品牌说明，并同步服务器隐私模板。确认跨团队提供数据的授权文案与实际接收人员一致；如存储地域导致跨境处理，需运营方确认相应告知及部署选择。本问卷不收证件、孩子姓名、学校名称。
6. 修改前端`public/config.js`为 `window.SURVEY_CONFIG = { apiBase: 'https://后端域名', adminBase: 'https://后端域名/admin.html', preview: false };`。把Pages“顾问入口”指向后端；不要使用Pages上的后台页面访问其本域API。后端`COLLECTION_ENABLED=true`仅在上述内容确认后开启。
7. 将源代码推到用户确认的仓库，在Settings → Pages选择GitHub Actions。仓库若要求发布审批，设置github-pages环境审批者。工作流只可手动运行，不会因推送自行公开。用户明确批准发布后才执行工作流，成功结果返回实际访问网址，不能把占位网址当成已上线网址。
8. 用虚构资料在正式HTTPS环境验证：手机完整填写、修改分支、成功回执、后台登录及分流、未登录401、错误来源403、撤回／删除。验证后删除测试资料。运营方还须验证家长所在网络环境的可达性。

GitHub Pages官方说明：https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

## 数据与运营

每个线索为一个AES-256-GCM加密文件，随机文件名与随机nonce，授权版本与时间保存于加密记录。评分在服务器计算，忽略客户端提交的分数及隐藏分支答案。只有持有后台会话令牌能读取或删除。后台不向第三方邮箱或CRM自动发送敏感资料；当前收件渠道是授权后台。若选择邮件提醒，建议只传回执ID，详情登录后台查看。

服务启动后及每小时清理超过保存期限的线索；后台读取也执行期限检查。删除请求通过后台处理，还需同步处理备份的保留与清理。修改密钥前必须安排迁移，密钥丢失无法解密。

当前仅适合单管理员、小规模首发。正式运营前，需按实际部署完成TLS、存储卷权限、密钥托管、加密备份、数据删除与恢复演练；多顾问需独立账号、最小权限及访问审计。源码测试不能替代真实托管环境验证。
